## Key Design Decisions (Already Made)

**CLAUDE.md hierarchy — additive, not inheritance**
All applicable CLAUDE.md files are loaded simultaneously into context — they stack, not override. Global sets behavioral preferences. Project adds repo-specific facts. Agent file defines the persona. No layer should repeat what a higher layer already covers.

**Global CLAUDE.md** (`~/dotfiles/claude/CLAUDE.md`) — behavioral and workflow preferences only. Not domain-specific. Not project-specific. Already rewritten and done.

**Project CLAUDE.md** (`.claude/CLAUDE.md` per repo) — generated by the `/init-project` skill. Not in dotfiles. Committed to each repo. Contains: what the project does, directory structure, build/test commands, conventions.

**Subagents = who Claude is. Skills = what Claude does.**
Skills orchestrate workflows and invoke subagents for judgment calls. Subagents are specialized workers with their own isolated context. Never mix them up.

**Claude Code primitives (confirmed from docs):**
- **CLAUDE.md** — loads every session automatically. "Always do X" rules and context.
- **Subagents** (`.claude/agents/`) — isolated execution contexts with specialized personas. Invoked by Claude or explicitly. Have `name`, `description`, `tools` frontmatter.
- **Skills** (`.claude/skills/name/SKILL.md`) — reusable workflows and knowledge. Create slash commands (`/name`). Supersede the old `.claude/commands/` format. Key frontmatter: `disable-model-invocation: true` (only user can invoke), `user-invocable: false` (only Claude can invoke).
- **MCP** — external tool integrations
- **Hooks** — shell commands triggered on events (PreToolUse, PostToolUse, etc.)

**Two code review subagents (not one)** — the posture and output format are genuinely different:
- `code-reviewer` → reviewing your own code before pushing. Blunt, assumes intent, focuses on "what should change." Priorities: correctness → security → design → performance → clarity.
- `pr-reviewer` → reviewing someone else's PR. Constructive, infers intent charitably. Three-phase workflow: context gathering → executive summary → architecture review → detailed review.

**PR review workflow (encoded in pr-reviewer agent):**
Kyle's actual workflow: checkout branch → `git diff main... > file.diff` + `tree > tree.txt` → feed to LLM → iterate context gathering → three phases (summary, architecture, detail) one at a time with discussion between each. The `/review-pr` skill automates the diff/tree generation.

**Whole-directory symlink** — `~/.claude → ~/dotfiles/claude`. setup_claude.sh updated. Root .gitignore already has the right runtime exclusions (`claude/projects/`, `claude/statsig/`, etc.).
